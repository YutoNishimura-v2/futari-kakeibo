# ふたりの家計簿

iOS 17 以降で、ふたりの支出を記録するアプリ。ホームの「今月の精算額」をタップすると、月の支出一覧・費目別合計・精算状況が開きます。右上の「ふたりと共有」からパートナーを招待できます。共有データは Apple の iCloud に保存します。

## 精算の決まり

- 金額は整数の円で記録します。折半・比率で1円未満が出る場合は、立て替えていない人の負担を切り捨て、**余りの1円は支払った人の負担**にします。101円を折半すると、支払った人が51円、もう一人が50円を負担します。
- 比率はふたりの負担割合を入力し、合計を100%にします。固定額では「わたし」側の負担額を入力し、もう一人が残りを負担します。
- 選んだ月の立替分を相殺し、差額と支払う方向を表示します。精算済みの月は未精算額から外れます。支出と費目別合計は残り、精算済みを解除すると追記できます。
- 支出の日付は端末で選んだ暦日として保存します。端末のタイムゾーンが変わっても、記録済みの支出は同じ月に残ります。

## 開発

XcodeGen が入った macOS では、次のコマンドで署名なしのシミュレータ向けビルドを実行できます。GitHub Actions も同じ構成です。

```sh
xcodegen generate
xcodebuild -project FutariKakeibo.xcodeproj -scheme FutariKakeibo -configuration Debug -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

精算ロジックは `Sources/FutariDomain` にあります。`checks/` の Node テストは、精算に加えて、メンバーの対応、旧データの移行、競合時の採用順を固定データで検査します。

既定ブランチの更新時に、GitHub Actions の「iOS screenshots」がシミュレータでライト・ダーク各6画面を撮影します。結果は `ci-shots` ブランチの `index.md` で見られます。ローカルの Xcode から試すには、生成したプロジェクトで `FutariScreenshots` スキームを選び、iPhone シミュレータでテストします。

## 有料プランの開発確認

家計簿の追加・費目別予算・定期入力などの鍵から購入画面を開けます。月額・年額・買い切りの3種類があり、最初に年額が選ばれます。対象の方には年額で14日間の無料体験があります。「購入を復元」で同じ Apple Account の購入を取り込めます。

**共有家計簿は、持ち主か参加中のパートナーのどちらか一人に有効な購入があれば、二人とも Pro になります。** アプリは StoreKit で確認した購入情報を、自分が書き込める各家計簿のストアへメンバー別に保存します。共有先には iCloud の同期後に届きます。買い切りが有効な間は期限がなく、ふたりとも有効な購入がなくなると無料に戻ります。解約した定期購入は有効期限まで使えます。払い戻しなどの取り消しは StoreKit の更新を受け取った端末から同期されます。Apple のファミリー共有も3商品で有効に設定します。

XcodeGen で生成したスキームは、Run → Options → StoreKit Configuration に `FutariKakeibo.storekit` を設定します。そのままローカルで購入・復元・期限切れを試せます。App Store のサンドボックスで試す場合は同じ欄で「None」を選びます。ローカルの価格は仮です。商品 ID、署名、法務ページの公開、正式な価格の登録は[提出チェックリスト](docs/release-checklist.md)を参照してください。購入を介さず動作を確認する場合は `LEDGER_PLAN=pro` で開発用ビルドを作れます。

- 家計簿は右上の「ふたりと共有」から追加・切り替え・招待できます。自分の家計簿を追加するには、自分の Apple Account で有効な購入が必要です。パートナーの購入で使える有料機能は、二人で共有している家計簿に適用されます。予算は「月の明細」の「費目別予算」で、その家計簿の選択月に設定します。残額は費目別の合計の行に出ます。
- 定期入力は「ふたりと共有」から追加します。アプリが開いた月に生成されます。iCloud を使う場合は、起動後に対象のストアで最初の取り込みが終わってから生成します。精算済みの月は解除するまで追記されません。アプリを開かなかった月の支出はさかのぼって生成しません。定期入力の ID は家計簿・定期入力・月から決まるため、2台が同じ月に開いても明細には1件だけ表示されます。
- 追加の家計簿で Pro の権利が切れると、持ち主とパートナーの両方の「ふたりと共有」に鍵付きで表示されます。鍵から購入画面を開けます。招待で参加した家計簿は、同じ画面の「共有の管理」から参加を終了できます。
- 「ふたりと共有」→「家計簿の便利機能」から、年間と前月比の支出、選択中の家計簿の CSV、買い物リスト、費目、テーマ、精算日の通知を開けます。追加した費目は支出・定期入力・予算で選べます。テーマと通知日は端末ごとの設定です。
- 精算日の通知は指定した日（短い月は月末）の朝9時に月1回です。購入の有効期限内で翌年の同じ月まで予約し、アプリを開くたびに先の月を補充します。
- ウィジェットは直近に開いた家計簿の今月分を表示します。月が変わったらアプリを開いて更新します。実機では `LEDGER_APP_GROUP` に登録済みの App Group を指定し、アプリ本体とウィジェットの App ID の両方で同じグループを有効にしてください。

## 共有と移行

- 持ち主の家計簿は CloudKit の非公開ストア、招待を受けた家計簿は共有ストアに入ります。招待は指定した Apple Account １人に書き込み権限を付けます。相手が参加すると共有の家計簿が開き、右上から自分の家計簿にも戻れます。承諾前の招待は、新しい相手のリンクを作ると差し替わります。
- 支払った人と負担割合は、持ち主とパートナーの固定の参照を使います。表示名を変えると過去の明細にも新しい名前が表示されます。支出入力の初期値は自分です。
- 旧版の支出、精算済みの月、変更した名前は初回起動時に自分の家計簿へ移行します。支出の ID と負担の内訳を引き継ぎます。iCloud を使う場合は最初の取り込みが済んでから移行先を決めます。すでに家計簿があれば再利用し、空の旧データからは移行用の家計簿を作りません。
- 両端末で同時に変更した場合、名前はメンバーごと、精算状態は月ごとに、更新時刻が新しい編集を採用します。同時刻は編集 ID の辞書順で決着します。すでに取り込んだ編集を更新する場合はその時刻より先に進めます。オフラインで同時に変えた場合は端末の時計差が結果に影響します。追加した支出はそれぞれ残ります。

## 実機２台で確認する

`project.yml` の `LEDGER_CLOUD_CONTAINER` を Apple Developer に登録したコンテナ ID に差し替え、同じ App ID とチームで署名します。対象の App ID で iCloud（CloudKit）と Push Notifications を有効にしてから XcodeGen で再生成します。プレースホルダーのままでは端末内の動作を試せます。開発環境でスキーマを作成し、TestFlight や配布ビルドを試す前に CloudKit Console で本番へデプロイします。[Apple の Core Data 共有サンプル](https://developer.apple.com/documentation/coredata/sharing-core-data-objects-between-icloud-users)

1. **上書き移行**。端末 A の旧版に３種類の負担ルールの支出と精算済みの月を作り、名前を変更する。同じバンドル ID の新しいビルドを上書きし、金額、日付、支払った人、精算状態、名前を比較する。再起動後も件数が増えないことを確かめる。
2. **招待**。異なる Apple Account の端末 A・B を使う。A で B のメールアドレスを指定し、メッセージなどでリンクを送る。B でアプリ起動中と終了中の両方を試し、承認後に A と同じ明細が開くこと、招待対象外のアカウントに転送すると参加できないことを確かめる。
3. **同期と競合**。A と B それぞれから支出を追加し、もう一方に届くことを確かめる。両端末をオフラインにして同じ名前や月の精算状態を変更し、再接続後に同じ結果になることを確かめる。同期エラー時は日本語の案内と再試行が出て、復旧後に消えることも確かめる。同期の時刻は iOS が決めます。
4. **共有を離れる**。B で「共有の管理」から参加を終了する。B で自分の家計簿が開き、A では共有していた明細が残ることを確かめる。A を再度開き、共有を離れた案内と再招待を確認する。
5. **iCloud 未使用**。サインアウトした端末で案内が１行で表示され、支出追加や精算が端末内で使えることを確かめる。
6. **持ち主の２台目**。端末 A に共有済みの家計簿がある状態で、同じ Apple Account の端末 B に新規インストールする。初回取り込みの後に A の家計簿が開き、B の追加が A に届くことを確かめる。B に旧ビルドで作った空の自分の家計簿がある場合も試す。
7. **承諾前の差し替え**。端末 A で別の Apple Account を指定してリンクを作り、誰も受け取っていない状態で端末 B のアカウントに差し替える。B の承諾後は、別の相手への差し替えが拒否されることを確かめる。
8. **レシート写真**。共有済みの家計簿を使っている端末 A・B を上書き更新し、既存の支出を開けることを確かめる。A の支出詳細で縦向きの写真を追加し、B の同じ支出に向きの正しいサムネイルが届き、タップで全画面表示できることを確かめる。B で削除し、A にも削除が反映されることを確かめる。
9. **定期入力と家計簿の分離**。有料プランのビルドを入れた A・B で追加の家計簿を共有し、月替わり前に定期入力を2件同期する。B をオフラインにしてアプリを終了し、A で片方を停止する。月替わり後に B を開き、取り込み前には今月の定期入力がなく、再接続して取り込んだ後には有効な定期入力だけが1件出ることを両端末で確かめる。もう一方の家計簿に切り替え、支出・予算残額・精算状態が分かれていることを確かめる。
10. **定期入力の写真の競合**。両端末で同じ定期入力が作られ、互いの支出のコピーがまだ届いていない間に、同じ明細へ別々の写真を追加する。同期後、競合の案内と両方の写真が表示されることを確かめる。片方の端末で1枚に差し替え、もう片方でもその写真1枚だけになることを確かめる。
11. **費目と買い物リスト**。A が追加した費目を B で選び、費目別予算と支出を記録する。A と B がオフラインで別々の品目を追加してチェックし、再接続後に両方の変更が届くことを確かめる。別の家計簿に切り替えて品目と費目が分かれていることを確認する。
12. **グラフ・CSV・ウィジェット・通知**。Pro ビルドで支出と予算を入力し、月・年をまたぐ棒グラフ、CSV の日付と引用符を含むメモ、ウィジェットの残額と自分の支払額を照合する。通知日を31日に設定し、短い月に月末の通知が1件届くこと、オフにすると次回の通知が止まることを確認する。無料ビルドでは有料機能が鍵付きになり、ウィジェットに金額が出ないことを確認する。
13. **購入と共有**。開発用の CloudKit 環境で通常ビルドを使い、ファミリー共有を設定していない別々の Apple Account で共有家計簿に参加する。まず持ち主、別の試行で参加者が購入し、同期後に相手も同じ家計簿で Pro になることを確認する。購入済みの端末で再インストールし、初回の取り込み中は購入確認のエラーが出ず、取り込み後に Pro が反映されることも確認する。年額の無料体験と復元を試し、最後の購読の期限切れや買い切りの払い戻し後は、追加の家計簿に両端末で鍵が出ることを確認する。
